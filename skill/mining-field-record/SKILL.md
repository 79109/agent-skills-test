# mining-field-record

把零散现场材料串成可回查的记录，让后来接手的人能知道发生了什么、依据在哪里、还有什么尚未确认。

## 核心能力

- **多种材料关联**：把文字、照片、测点与样品对应到同一对象或事件，减少漏记与重复。
- **还原事件经过**：区分发现、记录、处置和复查，保留时间顺序与状态变化。
- **直接形成可用文稿**：按现有台账或报告习惯整理事实，突出缺项和需要核对的矛盾。

## 开始时

确认资料涉及的区域、时段和用途，读取现有表格或报告模板。只需要台账时集中整理记录；需要报告时，再围绕重点问题组织叙述，不额外扩展为原因诊断。

## 工作流程

1. 识别记录对象、时段和报告用途。
2. 资料较多时生成文件索引，再核对照片、测点、样品和事件对应。
3. 提取事实与时间线，显露冲突和未确认的关联。
4. 沿用现有格式形成台账或报告，依据复查证据更新状态。

## 按需使用资源

- 使用本地工具前，阅读 [参数与适用范围](references/tool-usage.md)，再调用 [scripts/index_evidence.py](scripts/index_evidence.py)。工具仅处理所说明的格式和能力，不代表完整任务已完成。
- 方法选择、边界判断或复杂情形：阅读 [references/methods.md](references/methods.md)。
- 需要快速组织交付内容时，复制并裁剪 [assets/field-log.csv](assets/field-log.csv)；这是可选起点，不是固定输出格式。

## 交付

交付整理后的台账或报告草稿，并随正文指出影响核对的缺项；资料复杂时附必要的证据索引或时间线，简单任务不增设附件。

文字应能区分已观察、已记录和待核实。记录整理不代表现场问题已解决；材料出现正在发生的危险征兆时，提示交由现场值守人员按现行流程处理。
