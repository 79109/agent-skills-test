# mining-simulation-analysis

帮助用户判断模型是否抓住了主要机制、哪些参数真正影响结论，以及计算结果能够支持怎样的工程解释。

## 核心能力

- **从问题选择模型**：依据变形、破坏或渗流机制选择表示方法和简化程度。
- **定位关键参数**：围绕目标响应组织敏感性分析，区分参数影响、参数不确定性和模型误差。
- **检验结果可信度**：将数值检查、参数标定和独立数据验证分开，解释模拟与实测不一致的原因。

## 确定当前任务

读取工程条件、已有模型、软件环境和目标。没有模型时形成建模方案；已有模型时先审查关键假设；已有输出时从可比性和结果解释入手。只有确实可调用求解器时才执行计算，并保留运行状态。

## 工作流程

1. 把工程问题映射到目标响应、机制和模型简化。
2. 检查参数来源、边界、计算阶段及数值验证；依据实际工具选择运行或分析已有结果。
3. 在可比工况下比较参数影响；需要单因素数值对比时使用脚本，其余情况按对应设计分析。
4. 用独立观测和模型假设解释结果，报告失败工况及适用范围。

## 按需使用资源

- 使用本地工具前，阅读 [参数与适用范围](references/tool-usage.md)，再调用 [scripts/compare_cases.py](scripts/compare_cases.py)。工具仅处理所说明的格式和能力，不代表完整任务已完成。
- 首次了解输入格式时，查看合成样例 [examples/cases.csv](examples/cases.csv)；演示数据不可当作实际测量或规范参数。
- 方法选择、边界判断或复杂情形：阅读 [references/methods.md](references/methods.md)。
- 需要快速组织交付内容时，复制并裁剪 [assets/model-brief.md](assets/model-brief.md)；这是可选起点，不是固定输出格式。

## 交付

围绕用户最关心的问题给出模型方案或分析结论、关键证据、敏感参数及下一步改进。需要计算时可生成与现有软件匹配的配置、脚本或工况表；需要展示时提供可比较的图表。

明确区分拟运行方案、用户提供的结果和本次实际计算。没有求解结果时不生成虚构云图、位移或安全系数，也不把模拟结论直接当成现场验收结论。
