# mining-data-preparation

解决“文件能打开，但数据不能直接比较”的问题，让多来源记录在保留现场变化的前提下进入后续分析。

## 核心能力

- **多源对齐**：把仪器输出、测点台账和采掘日志按时间、空间及对象关联。
- **有依据地清洗**：识别重复、缺测、漂移和单位问题，避免把真实工程异常当噪声消掉。
- **处理过程可回查**：保留原始值、变换依据和记录映射，支持复核及重复处理。

## 开始时

先了解数据将用于绘图、统计比较、异常识别还是建模，再检查文件结构、字段含义和覆盖范围。处理粒度由分析目标决定；已有数据规范优先沿用，不强制转换为统一模板。

## 工作流程

1. 识别记录粒度、字段含义与下游分析用途。
2. 先用本地画像工具查看字段、缺测、重复和时间覆盖，再结合工况解释问题。
3. 根据明确规则在副本上转换、关联或清洗，保留原值和记录映射。
4. 核对处理影响，交付可用数据和仍限制分析的问题。

## 按需使用资源

- 使用本地工具前，阅读 [参数与适用范围](references/tool-usage.md)，再调用 [scripts/profile_csv.py](scripts/profile_csv.py)。工具仅处理所说明的格式和能力，不代表完整任务已完成。
- 首次了解输入格式时，查看合成样例 [examples/monitoring.csv](examples/monitoring.csv)；演示数据不可当作实际测量或规范参数。
- 方法选择、边界判断或复杂情形：阅读 [references/methods.md](references/methods.md)。
- 需要快速组织交付内容时，复制并裁剪 [assets/data-dictionary.csv](assets/data-dictionary.csv)；这是可选起点，不是固定输出格式。

## 交付

有实际文件时，交付可分析的数据副本及必要的字段说明、问题标记和简洁处理记录。若只需要检查，则聚焦影响分析的主要问题和修正建议。输出格式沿用用户工作流，不为了展示而重复生成多套数据。

清洗完成不等于工程状态正常；原始记录中的异常现象应留给后续分析和复核。
